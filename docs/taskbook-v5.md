# 知农时 V5 任务书（V5.3）

**版本**：V5.3（替代 V5.2 / V5.1）
**日期**：2026-10-31
**基线**：`main` 分支，`frontend/tests/pages.test.js` 140 项断言全绿
**适用范围**：全员。按功能模块认领，不严格区分前后端

> 本版相比 V5.2 的变化：不再往"功能数量"上加东西，而是把**系统的判断方式**
> 改成人的判断方式 —— 明显不对的事要拦、说不准的事别装准、同一件事只做一遍、
> 渔业不是新板块而是地块的一种、能不能装传感器让用户自己决定。

---

## 一、这版要解决的六个判断

前几版任务书一直在回答"还缺什么功能"。这一版的出发点是六个具体的不满：

| # | 现状（可复现） | 该有的样子 |
| --- | --- | --- |
| 1 | 地块评分只看 5 个因子，光照、风害这些直接影响收成的反而没算 | 因子要覆盖真正影响产量的自然条件，且每项都要有数据来源 |
| 2 | 输"水稻 + 12 月 + 哈尔滨"照样生成一条排得整整齐齐的日历 | 明显不成立的组合直接拦住，并给出可执行的替代方案 |
| 3 | 三个月后的节点写着"9 月 17 日有雨，不宜喷药" | 远期只说"9 月中下旬常年雨日偏多"，具体哪天子临近再看 |
| 4 | 面积算法 4 份、区划推断 2 份、鱼种数据 2 份、JSON 解析 5 份 | 同一件事只有一处实现 |
| 5 | 渔业是侧栏里一个独立板块，和地块、作物互不相干 | 渔业是农业的拓展：地块类型选"鱼塘"就自带养殖日历与水质 |
| 6 | 所有数据都是模型推算，用户想接探头也无处可接 | 用户自选接入传感器/摄像头，接了就以实测为准，没接就标明是估算 |

一句话：**V5.3 的目标不是"更多"，是"更像人"**。

## 三、农事日历：从"排日期"到"像人一样安排"

### 3.1 播种前必须过常识（已落地）

**新增接口** `GET /api/sow-check?crop=&sowDate=&lat=&lon=`

五类规则，每条都独立判定、独立给建议：

| 规则 | 判定 | 级别 |
| --- | --- | --- |
| 作物是否认识 | 作物库无此品种（如"冬小麦"未收别名时） | **阻断**，并给候选 |
| 区域是否对口 | 主产区与地块区划不符 | 跨气候带**阻断**，同带**提醒** |
| 日期是否合理 | 未来 >120 天 / 过去 >2 年 | **阻断** |
| | 未来 60~120 天 | 提醒"属远期计划" |
| | 已过全生育期 | 提醒"可复盘" |
| 播季是否对口 | 月份不在 `suitableSeason` 内 | 偏离 >1 月**阻断**，擦边**提醒** |
| 霜冻与积温 | 播期落在常年霜期 | **阻断** |
| | 生育后期撞霜 / 生育期长于无霜期 | 提醒 |

**几条刻意的取舍**（都是踩过的坑）：

- **区域不匹配不一刀切**。水稻主产区写的是"华南、长江流域"，但华北有小站稻、
  东北有盘锦稻，直接拦会误伤真实种植。只有"华南专属作物 → 东北/西北/青藏"
  这种跨气候带才拦。
- **区划同义词必须收全**。属性库是人整理的，小麦写"黄淮海平原"、大豆写"东北、黄淮海"，
  如果只按"华北"字面比，济宁种小麦会被判成不适种。
- **"太远"不等于"不合理"**。秋播、育苗移栽提前一两个月安排是常态，
  所以 60 天内算正常计划，60~120 天只提醒"远期"。
- **认不出作物不放过**。`standardName()` 对不认识的输入会原样返回，
  早期版本据此判空导致"冬小麦"被当成已知作物放行 —— 现在改用搜索结果的首条
  是否为精确/别名命中来判断。

**前端行为**：

- `ok` → 直接生成
- `warn` → 列出提醒，用户点"我知道了，仍然生成"才继续
- `block` → 不生成，列出每条原因 + 建议；若算得出替代日期，给"改用 X 月 X 日"一键改期
- 校验接口不可用 → 不阻断，但明确提示"本次未校验"

### 3.2 远期节点不再假精度（已落地）

**旧实现的问题**：预报只有 7~10 天，超出的日期拿"去年同一天"的天气补位，
然后照常打分。于是三个月后的节点会输出"9 月 17 日 有雨，不宜喷药"——
日期精确到天、结论精确到能不能干活，但依据是去年的某一天。

**现在的口径**：

| 距今天数 | 精度 | 结论形态 | 依据 |
| --- | --- | --- | --- |
| ≤10 天 | `forecast` | "当天有雨，不宜喷药，建议顺延到 X 日" | 真实预报 |
| >10 天 | `season` | "预计 9 月中旬，具体打药日等临近 7 天预报再定；该时段常年雨日偏多" | 近 3 年同期气候 |

**常年值怎么来的**：一次请求取回近三年逐日数据，按"一年中的第几天"聚合，
任意窗口可查（`ClimateNormals`）。返回日均温、最高/最低、雨日占比，
并在界面上写明"非预报，依据近 3 年同期（前后 7 天）气候"。

**前端区分**：远期节点用虚线卡片 + "远期计划 · 非预报" 标签 + 常年概览一行，
`certainty=planned`，不会和"预报说那天不宜打药"混在一起。

### 3.3 日历还剩的问题（P1）

| 问题 | 现状 | 下一步 |
| --- | --- | --- |
| 茬口冲突 | 同一地块前后两季没有互相校验 | 生成时读该地块已有作物，检查收获日与新播期是否重叠 |
| 播期建议只用节气 | 没结合当年积温与品种熟期 | 用 `ClimateNormals` 算出"积温达标日"作为第二个建议值 |
| 节点不可拖动 | 只能看不能改 | 允许用户改节点日期，改后重算受影响的后续节点 |

## 四、评分体系：因子扩展

### 4.1 当前七因子（已落地）

| 因子 | 数据来源 | 算法要点 | 归一权重 |
| --- | --- | --- | --- |
| 地形 | Open-Meteo 90m DEM，多边形内 ≤30 点采样 | 最小二乘拟合平面求坡度；梯度方向求坡向（坡向 <1° 标"平地"） | 0.20 |
| 土壤 | Open-Meteo 土壤模型（0/6cm 地温、0-1cm 含水率） | 墒情适宜带 0.20~0.35；地温 12~25℃ 满分 | 0.17 |
| 气候 | 实时气温湿度 + 未来 7 天降水 | 气温 15~28℃、降水 10~60mm 为最优 | 0.16 |
| **光照** | 未来 7 天累计短波辐射 / 7 | ≥18 MJ/m²·d 满分；阳坡 +6，阴坡 −10 并记限制因子 | 0.13 |
| **风害** | 未来 7 天最大风速（km/h→m/s） | 6 级（10.8m/s）以上判高风险；地块内有凸起再 −5 | 0.09 |
| 形状与规模 | 球面投影 shoelace + 周长 | 紧凑度 4πA/P²；面积分档 | 0.11 |
| 排水与保水 | 坡度 + 降水 + 含水率 | 平地+多雨判易涝；陡坡判流失风险 | 0.14 |

**两条不能破的规矩**：

1. **取不到的项不参与**，权重按剩余项重新归一，绝不用默认值凑一个中间分。
2. **模型算的必须标"估算"**，并写清推算依据（如"饱和溶氧 × 70%，连日阴雨光照不足"）。

### 4.2 待补因子（P1，按数据可得性排序）

| 因子 | 为什么值得加 | 数据从哪来 | 风险 |
| --- | --- | --- | --- |
| 土壤质地 | 砂土/黏土的适种范围差别很大 | ISRIC SoilGrids WMS（此前网络不可达，需再验证） | 不可达时只能维持区域规则 |
| 水源可达性 | 灌溉成本直接决定种什么 | Overpass API 查最近水体/渠道距离 | 请求慢，需缓存 + 超时降级 |
| 交通可达性 | 农机与运销的硬约束 | Overpass 查最近道路等级 | 同上 |
| 连片度 | 决定能否上大农机 | 相邻地块是否登记在同一用户名下 | 依赖用户数据量，早期样本不足 |
| 历史投入 | 地力有惯性 | 该地块历年种植记录 + 施肥记录 | 需要用户持续记录 |

**加因子的三条准入**：有真实数据源、能和产量建立可解释的关系、缺数据时能干净地退出。

## 五、渔业并入地块（已落地）

### 5.1 信息架构调整

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 侧栏 | 独立"渔业"入口 | 移除，归入"我的 → 我的地块" |
| 入口 | 选品类 → 填放养日 → 生成日历 | 地块类型选"鱼塘"，详情页内即见 |
| 数据 | `IndustryHandler` 与 `PondStatusHandler` 各存一份鱼种 | 统一 `SpeciesCatalog` 读 `species.json` |
| 功能 | 只有生产日历 | 生产日历 + 水质状态 + 投喂量 + 泛塘风险 |

### 5.2 鱼塘详情页的四块内容

1. **空间分析**：塘址坡度、水源条件、塘埂建议（沿用 `PlotAnalyzeHandler` 的 pond 分支）
2. **水质与投喂**：水温、溶氧（含凌晨最低）、pH、氨氮、今日投喂量
3. **养殖日历**：按放养日生成 放苗/开食/投喂/换水/起捕
4. **监测设备**：水温、溶氧探头（见第六章）

### 5.3 仍未做

- 塘口容积与换水量计算（需要平均水深，目前只有面积）
- 多塘轮捕的存塘结构（同一品种多批次）
- 饲料系数与养殖成本核算

## 六、传感器与监控：可选接入

### 6.1 设计原则

**默认什么都不装。** 不装就用模型推算，界面上写清"模型估算"；
装了就用实测覆盖，并在结论里标"实测"。系统不因为用户没设备就罢工，
也不因为没设备就假装数据很准。

### 6.2 支持的设备

| 设备 | 用途 | 参与的计算 |
| --- | --- | --- |
| 土壤墒情 | 0-1cm 体积含水率 | 地块评分"土壤"因子、干旱限制因子 |
| 土壤温度 | 地表温度 | 地块评分"土壤"因子、低温提醒 |
| 水温 | 池塘水温 | 溶氧饱和值、投喂率、高温/低温风险 |
| 溶解氧 | 塘内溶氧 | 泛塘预警（优先于模型值） |
| pH / 氨氮 | 水质 | 水质风险与处置建议 |
| 小型气象站 | 田块小气候 | 预留：接入后替代区域预报 |
| 摄像头 | 现场画面 | 快照预览（不做图像识别） |

### 6.3 数据来源三档

| 来源 | 状态 | 说明 |
| --- | --- | --- |
| 手动录入 | 已支持 | 用户抄仪表读数，最现实的一档 |
| 网络接口 | 已支持填地址，未做定时拉取 | 下一步加后端代理，避免跨域与密钥暴露 |
| MQTT | 仅占位，界面标"预留" | 不假装能连 |

### 6.4 三条约束

1. **读数有时效**：超过 24 小时标"可能已过期"，水温超过 6 小时不参与投喂计算。
2. **实测进缓存键**：否则先算过模型值的地块，接了传感器仍返回旧结论（已修）。
3. **设备属于地块**：删地块时提示"该地块有 N 台设备"，由用户决定是否一并移除。

### 7.1 已收口

**两个真实事故**：

1. `PondStatusHandler` 硬编码的草鱼适温与 `species.json` 不一致，

2. Open-Meteo 响应里 `daily_units` 有 `"precipitation_sum":"mm"`，
   三份解析实现里有两份会先撞上它，导致降水恒为 0 却毫无报错。

## 九、验收清单

### 9.1 播种校验

1. "水稻 + 12 月 + 哈尔滨" → 阻断，至少给出"气候带不符""播期不在适播季""播期在霜期"三条。
2. "玉米 + 11 月 + 济宁" → 阻断，并给"改用次年 3 月 1 日"这类可执行建议。
3. "小麦 + 10 月 + 济宁" → 通过，不出现"主产区不在本地"的误报。
4. 输入作物库没有的名字 → 阻断，并给出候选。
5. 前端在阻断时**不允许**跳到日历页。

### 9.2 远期精度

1. 生成一份 8 个月后的日历，所有 >10 天的节点 `precision=season`。
2. 远期节点文案里**不出现**"某月某日 有雨/无雨"。
3. 远期节点必须带"非预报"标记与常年概览（日均温、雨日占比）。
4. ≤10 天的节点仍是 `forecast`，可以说"当天"。

### 9.3 评分

1. 返回 7 个因子（数据齐全时），权重归一后合计 = 1.00。
2. 断网时地形因子消失，其余因子权重重算，`score` 不出现 null 或 0。
3. 丘陵地块能识别坡向，平地标"平地"而不是硬给一个方位。

### 9.4 渔业并入

1. 侧栏无"渔业"入口。
2. 地块类型选"鱼塘"后，详情页出现水质面板与养殖日历。
3. 养殖日历的品种列表与 `/api/industry/species` 一致，不出现前端独有的品种。

### 9.5 传感器

1. 不接设备时，所有数值标"模型估算"。
2. 接入溶氧探头并录入 3.2 mg/L 后，泛塘预警改用实测值，标注"实测"。
3. 同一地块先算模型、再接设备重算，结论必须变化（缓存键已含实测值）。
4. 移除设备后，结论回到模型估算。

## 十、边界与风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 属性库用词不统一 | 区划/播季判断误伤 | 同义词表 + 每加一批作物就回归一次；误判可被用户覆盖 |
| 常年值仅 3 年 | 极端年份拉偏平均 | 界面写明"近 3 年"，不称"气候常年值" |
| 传感器靠手动录入 | 数据不连续，趋势无意义 | 明确标注读数时间；不做"趋势分析"这类需要连续序列的功能 |
| 摄像头多为内网地址 | 浏览器直接加载会失败 | 失败时给明确提示，不显示破图 |
| 设备数据存本地 | 换设备丢失 | P3 上持久化；当前在设备列表页提示"仅本机保存" |
| 播种校验可能过严 | 拦掉合法的特殊种植 | 所有"阻断"都给出理由与替代方案，不做无解释拦截 |

## 十一、与前面几版的关系

- **V4 的 15 个功能全部保留**，本版不删功能，只改判断方式。
