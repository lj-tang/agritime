## 七、V4 目录规范对照（T00）

V4 任务书里 `backend/` 那棵树是按「接口 / 业务 / 模型 / 中间件」分层画的**逻辑草图**。
本项目是纯 Java（javac 直接编译，没有构建工具），Java 的包路径必须和目录一一对应，
所以这四层落地为**包**，而不是 `backend/` 根目录下的四个文件夹：

| V4 目录 | 实际位置 | 内容 |
| --- | --- | --- |
| `backend/api` | `src/com/cropcalendar/api` | 全部 `*Handler`：timeline / crops / recognition / chart / plots / disease / geo / auth / admin / me / support |
| `backend/service` | `src/com/cropcalendar/service/**` | `geo`（逆地理编码）、`user`（账号库与用户数据） |
| `backend/model` | `src/com/cropcalendar/model` | `User` 等数据模型 |
| `backend/middleware` | `src/com/cropcalendar/middleware` | `Auth`：会话令牌与鉴权 |
| 既有 | `src/com/cropcalendar/{compute,orchestration}` | 计算层与编排层。属 T03/T04 的地盘，收口时再并入 `service` |
| 既有 | `src/com/cropcalendar/{util,config}` | JSON 工具、配置加载 |

前端 `pages/` 暂保持扁平。当前是「单页 + 面板切换」结构（`index.html` 内切换种植推荐 / 地块 / 日历 / 病害 / 我的作物），
要拆成 V4 的 `pages/recommend/`、`pages/plots/` 等子目录，得先做路由化改造 —— 那属于 T11 多端适配，
不在 T00 里强行拆分，避免只搬文件不改架构、变成两份要同步维护的代码。

数据层与共享层已按 V4 落位：`data/{crop-base,guidance,region,disease,schema,enums}`、`shared/{constants,utils}`、`docs/`。
`data/industries/`（渔业试点）与 `data/market/`（市场需求）由 T09 / T15 认领人补齐。
