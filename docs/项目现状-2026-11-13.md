## 七、风险与技术债（按优先级）

### P0 — 无 HTTPS

nginx 只监听 80，没有证书。三个直接后果：

1. 密码、会话 Cookie 明文过网；
2. 浏览器**不给** `navigator.geolocation`（非安全上下文），所以首页只能退到 IP 定位，精度到城市；
3. 微信小程序**必须** HTTPS 且域名备案，现在无法上线。

前面反复出现的"天气不可用""定位不准"，有一部分根子就在这里。

### P0 — 没有监控告警

单机部署，靠 systemd 自启，没有 uptime 探活、没有异常告警。服务挂了只能等用户发现。

### P1 — 文档落后一个版本

`docs/项目目录说明.md` 写的是 V4：15 个接口、102 项测试、"渔业待建"。实际是 **25 个接口、216 项测试、渔业早已上线**，还多了华东窗口、境外换算、城区三档、地图标点。新人照文档接手会被带偏。

### P1 — 大模型是单点，且缓存不持久

播期/日历首次生成要 30–40 秒；缓存是**进程内**，每次部署重启即清空，用户下一次请求又要等。上游限流时前端只能提示"请求过于频繁"。

### P1 — nginx 全局限流 30 次/分钟

`limit_req zone=agritime_limit rate=30r/m burst=10` 对 `/api/` 一视同仁。地图、天气、定位这类一次页面加载就要打七八个的接口，很容易把自己限死（今天我做回归测试就被限过三次）。建议按路径分级。

### P2 — 前端是巨石

`index.html` 2314 行（含全部内联脚本）、`my-plots.js` 2058 行、`common.css` 2275 行。没有构建、没有模块化，改一处要通读整段。

### P2 — 前端测试是字符串断言

216 项基本都是"读文件 → `includes('某段代码')`"，能防手滑，防不了真实渲染/交互回归。真正的验证靠人工 Playwright 脚本（`.dev/tmp/verify-*.js`），没进 CI。

### P2 — 城区判定是近似

用"离市中心/区驻地多少公里"替代真实土地利用，数据源（Overpass / 高德）在这台机器上不可达。会漏判（如广州天河），不会误拦（已放宽为三档 + 可强制继续）。

### P2 — 境外播期是换算值

按半球和纬度平移，没有当地农技资料。界面上已标注"按半球+气候带换算，非本地数据"，但结论精度有限。
