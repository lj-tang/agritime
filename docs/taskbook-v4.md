# 会看天的农事日历 · 功能扩展任务书 V4
**版本**：V4.0  
**日期**：2026-10-25  
**适用范围**：全员功能开发，统一收敛至 `agritime/` 目录，不分前后端，按功能模块认领

> **V4 变更说明（相对 V3）**：
> 1. 远期日程无天气可调用时，**不再弹出"天气数据暂不可用"提示**，改用大概时间/气候均值完成节点生成；
> 2. 播种时间改为双模式：**用户不输入时间 → 系统按最近适合播种的节气（如芒种）推荐起点**（推荐）；用户输入时间 → 从输入时间向后推荐；
> 3. 新增「我的作物」模块：记录已种作物状态、拍照分析，农事日历确认播种后自动加入；
> 4. 新增「我的地块」模块：标注农业地块（耕田/经济作物田/大棚/鱼塘等）、田地形状建模、实时温湿度监控；
> 5. UI 改版：左侧栏导航（种植推荐/我的地块/农事日历/病害检查等）、主页全屏化、修复夜间动画与加载 bug；
> 6. 新增「病害检测」：拍照/输入分析输出应对策略；
> 7. 产业扩展由"整体暂缓"改为**渔业试点先行**（鱼苗蟹苗类比种子，生成生产日历）；
> 8. 新增账号系统（含超级管理员后台），登录注册页与内部风格统一；
> 9. 新增客服系统：用户反馈 → 超管应答；
> 10. 种植推荐结合时间、地点、市场需求综合推荐。

## 一、项目整体目标
围绕**农事全链条指导、多模态交互、账号与安全、产业试点**四大方向迭代升级：保留原有三层架构与三档降级机制，核心接口性能维持 p95 < 2s；以"我的地块 + 我的作物 + 农事日历"为用户主链路，辅以病害检测、种植推荐、客服与超管后台，形成完整闭环。

### 模块4：时间体系、天气数据源分级与播种逻辑
**任务编号：T04**
- **任务描述**：
  1. **播种起点双模式**：
     - 方式A（推荐）：用户**不输入时间** → 系统按「地点 + 作物」自动获取最近适合播种的节气（如芒种）作为起点，生成全链条农事日历
     - 方式B：用户**输入时间** → 以输入时间为起点，向后推荐生成后续农事节点
  2. **远期日程无天气处理**：超出天气数据可调用的日程，**不弹出「天气数据暂不可用」提示**，直接用大概时间/气候均值生成节点（保证远日程也能出完整日历）
  3. 时间选择支持「手动输入」+「日期轮盘」两种交互，选择范围严格限制为：过去 2 年 ~ 未来 30 天
  4. 数据源分级：过去日期调用历史气象数据库，未来日期调用 Open-Meteo 预测 API；未来第 5 天起（含第 5 天）节点统一标注「天气为预测数据，仅供参考」
  5. **时间提醒**：关键农事节点（浇水、施肥、病虫害防治、采收等）支持开启提醒，前端展示倒计时，到点触发提醒通知
- **验收标准**：
  1. 不输入时间时，系统按最近适合播种节气自动生成日历；输入时间时，从输入时间向后生成
  2. 远期日程正常生成节点，无「天气数据暂不可用」类报错提示
  3. 日期选择器范围严格限制在过去 2 年 ~ 未来 30 天，超出不可选
  4. 未来第 5 天起节点有明确「仅供参考」标识
  5. 关键农事节点可开启提醒，前端展示倒计时，到点有提醒反馈
- **对应目录**：`backend/service/weather` / `backend/service/calendar` / `backend/service/reminder` / `frontend/components/date-picker` / `frontend/components/reminder` / `data/weather/`

- **对应目录**：`backend/service/recommend` / `data/market/` / `frontend/pages/recommend/`

## 五、开发与认领规则
1. **全栈认领**：每人认领完整功能模块，从数据、后端接口到前端页面全链路负责（参考第四章分工建议）
2. **优先级顺序**：
   - 第一批：T00（目录规整）
   - 第二批（核心）：T01（UI 框架）、T02、T03、T04（含播种逻辑）
   - 第三批（用户主链路）：T06（我的地块）、T12（我的作物）、T13（病害检测）
   - 第四批（增强）：T05、T07、T08
   - 第五批：T09（渔业试点）、T15（种植推荐）
   - 第六批（基建闭环）：T10（账号与超管）、T14（客服）、T11（多端）
3. **提交规范**：每个模块完成后提交对应目录代码，附带自测说明
4. **联调节点**：第二批完成后进行 1 次全链路联调；第三批完成后进行 1 次用户主链路联调
5. **验收节点**：每批完成后统一按验收标准检查一次

## 六、最终验收标准
1. 所有任务按验收标准可复现验证
2. 原有核心接口保持兼容，性能不退化（p95 < 2s）
3. 所有新增外部依赖（天气、定位、语音、图像分析等）均覆盖三档降级机制
4. 用户主链路「我的地块 → 种植推荐 → 农事日历 → 我的作物 → 病害检测 → 客服反馈」完整可走通
5. 账号系统、超管后台、客服系统可用；公网地址可正常访问
