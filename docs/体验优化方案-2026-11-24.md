# 知农时 · 整体体验优化方案

> 面向：农事日历 Web（及未来小程序）｜日期：2026-11-24
> 依据：线上现状审计 + UI 设计方法检索（来源见文末引用）

---

## 0. 设计原则（本次方案的总纲）

1. **说人话、给反馈**（尼尔森第 1、2 条）：每次操作都有可见结果；农事语言用「打药、浇水、施肥」而非系统术语；失败给重试按钮，不给空列表。
2. **首页是分发器，不是堆料**：信息聚合型主页围绕「产品与体验」提供入口，把用户最常做的事放在第一屏（B 站首页设计思路；美团金刚区功能导流 vs 点评内容流的取舍）。
3. **任务优先级决定模块顺序**：先回答三个问题——「这里能做什么、我现在进行到哪里、下一步点哪里」；首访与回访布局分开考虑。
4. **收敛字号层级**：3~4 档字号；需要区分层级时先调字重、颜色、间距，再考虑加字号；12px 只用于辅助文字。
5. **克制**（Ant Design「确定性」、Apple 排版逻辑）：能做，但想清楚了不做；间距按 4/8 栅格精确控制，完美 = 无可删减。
6. **适老化基线**（工信部《互联网应用适老化及无障碍改造专项行动方案》评测体系 + GB/T 47523—2026）：无衬线字体、可调字号；主要功能/主要界面文字最大字号 ≥30dp/pt，适老版主要文字 ≥18dp/pt；对比度 ≥4.5:1（字号 ≥18pt 的文本可 3:1）；主要组件点击区 ≥60×60pt、其他 ≥44×44pt；能点击就不滑动；适老版无诱导按键、无广告弹窗、首页有显著「长辈版」切换入口。
7. **状态收敛**：加载中 / 有数据 / 空 / 失败 四种状态统一为 pageState；用 requestVersion 防旧请求覆盖新请求；失败给重试按钮。

## 1. 现状诊断（已核实的体验问题）

| 维度 | 现状 | 影响 |
|---|---|---|
| 首屏负载 | 54 个静态请求、636.4KB raw / 191.1KB gzip、index.html 111KB、4 个内联脚本 | 弱网（农村 3G/4G）打开慢 |
| 首次使用 | 无引导；缺省坐标 35.07/116.31 对用户不可见；搜索结果无「热门/最近」 | 新用户不知道从哪开始 |
| 结果可读性 | 时间线节点信息平铺，无「今天该做什么」的强总结 | 老人/农户扫一眼拿不到结论 |
| 反馈与状态 | service.js 已有 20s 超时+重试，但其余页面 fetch 无统一超时/加载/空/错态 | 断网时页面「冻住」或空白 |
| 天气/数据新鲜度 | 时间线结果无「数据更新时间」标注（仅 dataTime 字段，前端未展示） | 用户无法判断结果是否过期 |
| 播期提示 | sowWindow 已上线但文案藏在 meta 区，无视觉强调 | 提示存在感弱 |
| 长辈模式 | 已有 font-scale 大字模式，但最大字号未达 30pt、点击区未系统化 ≥44pt | 未达工信部适老评测基线 |
| 外部依赖 | open-meteo（天气）、ipinfo.io（定位兜底）、AWS terrarium（地形）、高德瓦片 | 境外源超时会拖慢/挂起页面 |
| 一致性 | 卡片圆角/间距/阴影各页不统一；错误提示文案风格不一 | 拼凑感、信任感差 |

## 2. 信息架构方案

### 2.1 首页重排（page--home）

按「任务频率 × 任务价值」排序，从现在的平铺改为四层：

```
第一屏（首屏，用户 3 秒内做决定）
├─ 顶部一句话问候 + 今日节气/天气摘要（term-strip 精简为一行）
├─ 主卡片「今天地里该做什么」：
│   · 有地块+时间线 → 今日农事结论（做什么 / 天气是否支持 / 不下雨改哪天）
│   · 无 → 「查一查你种的东西」引导 CTA
└─ 查询表单（timeline-form）——保留但收敛为「作物 + 播期 + 位置」三要素，
   位置改为手动选择器（见 2.2）

第二屏
├─ 金刚区（4~5 个图标入口：时间线 / 我的地块 / 农事提醒 / 病害识别 / 节气）
└─ 最近查询 + 热门作物 chips（无登录也可用，存 localStorage）

第三屏（折叠/低频）
├─ 行业动态、地块 3D、更多工具 —— 折叠进「更多」或第二屏以下
```

首访 vs 回访：
- **首访**：表单上方显示三步引导条（① 选你在的地区 → ② 填作物和播期 → ③ 看整季安排），地区选择器直接内嵌在引导里。
- **回访**：「继续上次：水稻 · 3 月 20 日播种」卡片置顶（读 localStorage），不必重填。

### 2.2 位置与播期

- 把静默默认坐标改为**显式地区选择器**：省 → 市（复用 data/geo/places-cn.json 已有数据），选中后显示「已选：四川成都（30.67, 104.07）」，可改；未选时表单按钮置灰并提示「先选地区」。
- 播期输入保留日期选择器 + 快速选项：「我不确定播期」→ 系统推荐（已有 recommendedDate）。
- sowWindow 提示升级为表单内联的醒目条（绿=在窗口内，琥珀=不在窗口内但继续生成），不再只在结果 meta 里。

### 2.3 底部导航（移动端）

底部 tab 常驻 4 项：**首页 / 时间线 / 提醒 / 我的**（病害识别与地块并入二级入口），遵循「金刚区」导流思路，把低频功能收进「我的」。

## 3. 视觉系统升级（在现有令牌上做增量）

现有令牌已不错（brand #16a34a、radius 16px、dark 主题、41 断点、prefers-reduced-motion）。增量改动：

### 3.1 字号（收敛为 4 档）

| 档 | 用途 | 默认 | 长辈模式(font-scale) |
|---|---|---|---|
| 标题 | 页面标题、今日结论 | 20px | 30px+ |
| 主文字 | 卡片标题、按钮 | 17px | 24px+ |
| 正文 | 描述、表格 | 15px | 20px+ |
| 辅助 | 时间、来源、注释 | 12px | 16px |

- 长辈模式目标：主要文字 ≥18pt、最大字号 ≥30pt（对齐 GB/T 47523—2026 与工信部评测）。
- 行距 ≥1.3 倍，段落间距 >1.3 倍行距。

### 3.2 卡片规范（对齐 MD3 Cards）

- 圆角 12px、卡片间距 8px、卡片内边距 16px、标签/文字左对齐。
- 阴影只用一档 `--shadow`，删除多余装饰阴影。
- 每张卡片回答三件事：**这是什么、和别的有什么区别、点哪里继续**。

### 3.3 语义色与对比度

- 语义色：绿=适宜/正常（brand）、琥珀=注意（sun，播期窗口外/临近预警）、蓝=雨（rain）、红=危险（red，病虫害/超温）。文案永远配图标，不只靠颜色（适老化「颜色优于图形」反向：图形优于颜色）。
- 全站对比度走查：正文与背景 ≥4.5:1（`--muted #88928a` 在 #fff 上约 3.5:1，需加深为 ~#66706a 或仅用于辅助文字）；焦点态统一 `--focus-ring`。

### 3.4 间距

- 页面左右边距 16px，模块间距 8px（移动）→ 24px（桌面）；组内间距按 4px 栅格。
- 参考 Apple 排版：负空间优先，首屏只放一个视觉主角（今日结论卡）。

## 4. 页面级改造清单

### 4.1 首页（index.html）
- 按 2.1 重排；首屏请求目标：≤20 个、≤200KB gzip。
- 内联关键 CSS（首屏样式 <10KB），其余样式延后；大图（index-bg.png 65KB）改 CSS 渐变占位或 webp。
- 金刚区图标统一 SVG 单色 + aria-label。

### 4.2 时间线页（timeline.html）
- **今日结论 Hero 卡**：大标题「今天：给水稻灌水」+ 天气是否支持 + 「明天不下雨，可顺延」备选日期；结论由 todayConclusion 驱动（nodeId 已修）。
- **节点卡片四段式**：做什么（title）/ 为什么（description）/ 天气支持（weatherFactors → 「未来 7 天有雨，注意排水」）/ 备选（rescheduleAdvice）。operationType 配图标与语义色。
- 数据时间标注：「数据更新于 2026-11-24 14:20 · 来源：实时预报 / 缓存 / 本地兜底」。
- 生成中（202 轮询）状态：进度条 + 文案已有，补骨架屏（加载/空/错统一，见 §5）。
- sowWindow 醒目条 + 手动改播期的快捷入口。

### 4.3 地块、提醒、病害、后台
- 统一卡片规范与空态（「还没有地块，点击添加」+ 插图 + CTA）。
- 提醒列表按「今天/明天/以后」分组，逾期红色标注；提醒开关状态可视化。
- 后台 admin 沿用表格（管理 = 密集对比，用表格而非卡片，符合卡片方法论「表格比卡片更适合逐行核对」）。

### 4.4 状态与反馈（全站统一，pageState 模式）
```
state: loading → skeleton（保留布局的灰块，不是转圈）
       success → 内容
       empty   → 插图 + 一句话 + CTA（「还没有提醒，去添加」）
       error   → 一句话原因 + 重试按钮（「网络开了小差，重试」）
```
- 所有 fetch 走统一 request()（已有超时+重试的 service.js 扩展），带 requestVersion 防旧覆盖。
- 操作成功 toast：「已保存」「已删除，可撤销 10 秒内」（撤销提示符合工信部适老规范里「提交可逆」精神）。

## 5. 性能预算与实现

| 项 | 目标 | 手段 |
|---|---|---|
| 首屏 HTML+CSS+JS | ≤200KB gzip | 内联关键 CSS、合并 common.css 分段、去掉未用样式 |
| 首屏请求数 | ≤20 | SVG sprite、合并小图标、延后非首屏脚本 |
| 图片 | 每张 ≤100KB | webp + lazy + 尺寸属性 |
| 第三方瓦片 | 有兜底 | 高德瓦片失败回退简版矢量色块；AWS 地形超时降级为等高线提示 |
| 弱网 | 可用 | 时间线结果写 localStorage（上次结果+时间戳），离线显示「上次结果（离线）」 |

已有基础：PWA manifest/sw.js/pwa.js（不缓存 /api）、maplibre 按需加载、service.js 20s 超时。

## 6. 无障碍与适老化落地

- 触控目标：主按钮 ≥44×44px，长辈模式 ≥60×60px。
- 键盘焦点顺序与 :focus-visible 统一；装饰图标 aria-hidden（已有，保持）。
- 长辈模式补齐：字号达标（§3.1）、高对比背景（对比度 4.5:1 校验）、点击代替滑动（时间线节点折叠改为点击展开）、首页显著「长辈版」入口、设置里可常开。
- 语音：第一版不做全文朗读，保留 aria-live 关键播报（已有 role=status 的部分保持）。

## 7. 落地节奏（建议分三批）

**P0（体验主链路，1~2 周）**
1. 首页重排 + 首访三步引导 + 回访「继续上次」卡片
2. 位置手动选择器（省→市）替代静默默认坐标
3. 时间线「今日结论 Hero 卡 + 四段式节点卡片 + 数据时间标注」
4. 全站 pageState（加载/空/错 + 重试）+ 统一 request 封装
5. sowWindow 表单内联醒目条

**P1（视觉与适老达标，2~3 周）**
6. 字号 4 档 + 长辈模式 ≥18pt/30pt + 对比度走查（--muted 加深）
7. 卡片规范统一（12px 圆角/16px 内边距/8px 间距）+ 间距 4/8 栅格
8. 首屏性能：内联关键 CSS、SVG sprite、webp/lazy、第三方瓦片兜底
9. 底部导航（移动端）与金刚区收口

**P2（打磨，按需）**
10. 时间线结果本地缓存 + 离线「上次结果」标注
11. 语音提示、动效打磨、PWA 离线体验增强
12. 埋点（首页 CTA 点击、时间线生成时长、失败率）+ 反馈入口
